# Mevallar website redesign — sky, clouds, grass & flowers

Date: 2026-10-19
Status: Approved for implementation planning

## 1. Purpose

Redesign the Mevallar band website around a "blue sky" visual theme where
every clickable link is styled as a cloud, and page footers are illustrated
as grass with colorful flowers. Alongside the visual redesign, restructure
the site's content into a proper multi-page static site: a landing page,
a concerts section with per-concert pages (upcoming/past), a merch page,
and a linktree-style links page. The site remains a dependency-free static
site deployed to GitHub Pages at mevallar.com, now built via a small Node
script run by a GitHub Actions workflow so that source/build files are
never served on the live domain.

## 3. Visual design system

### 3.1 Color palette

Colors are extracted/approximated from the user's reference images
(band photos, merch shirt, show posters) and fully parametrized as CSS
custom properties in `:root`, so the palette can be swapped later by
editing one block of variables.

```css
:root{
  /* sky */
  --sky-top:#aed4ea;
  --sky-bottom:#eaf4fb;
  --cloud:#ffffff;

  /* grass + flowers (footer) */
  --grass:#5a9a3f;
  --grass-dark:#447a30;
  --flower-pink:#e85c86;
  --flower-orange:#ec9a3b;
  --flower-red:#e8432e;

  /* ink / neutrals */
  --ink:#2b2420;
  --paper:#fffdf6;
  --muted:#6b5c4e;

  /* accents */
  --lilac:#9c8db8;   /* primary accent — replaces the old --roof terracotta */
  --mustard:#d9a33e;
  --sage:#a9c6ae;
  --brown:#6b4a33;

  --line:rgba(43,36,32,.14);
}
```

`--lilac` is the new primary accent (buttons, eyebrow text, link underlines)
replacing the current site's terracotta `--roof`. `--mustard` and `--sage`
are secondary accents available for cards/highlights. Flower colors are
scoped to the footer illustration only.

Typography, spacing scale, and the `DM Mono` / `Space Grotesk` font pairing
from the current site are kept as-is.

### 3.2 Cloud nav / link component

A single reusable `.cloud-link` class used for **every** clickable link on
the site (topbar nav, hero CTAs, "buy tickets", "listen on Spotify",
footer socials, merch "buy" links, everything):

- Same puffy cloud silhouette as the current decorative `.cloud` elements
  (CSS-drawn body + `::before`/`::after` circles for the puffs), scaled down
  to button size.
- An `<a>` element with the link label centered inside the cloud shape.
- Hover/focus state: slight lift (`translateY`) + enlarged drop shadow.
- Must remain keyboard-focusable and have visible focus outline (the cloud
  shape must not remove default/custom focus styling for a11y).

### 3.3 Topbar navigation

Kept as a fixed/sticky header bar across every page except `/links/`
(which has no site chrome at all — see section 5.5). Each nav item is
rendered as a small `.cloud-link`.

### 3.4 Grass + flowers footer

Full-width CSS-illustrated footer:

- Grass silhouette: jagged top edge (via `clip-path` or layered rounded
  shapes) filled with `--grass`, a darker `--grass-dark` shadow layer
  underneath for depth.
- 4–6 small flower shapes (circle petals + center dot) scattered along the
  top edge of the grass, using `--flower-pink`, `--flower-orange`, and
  `--flower-red`.
- Footer content (social `.cloud-link`s for Instagram/Spotify/YouTube,
  email, copyright line) sits on/above the grass band.
- Used on every page except `/links/`.

## 4. Content/data model & build pipeline

### 4.1 Data file — `data/concerts.js`

Plain CommonJS module, no external dependencies:

```js
module.exports = [
  {
    slug: "20260521-parallel62",
    date: "2026-05-21",       // ISO date, used for past/upcoming comparison
    time: null,                 // "HH:MM" or null if unknown
    venue: "Parallel 62 Club",
    city: "Barcelona",
    address: "Avinguda del Paral·lel, 62, Ciutat Vella, 08001 Barcelona",
    mapUrl: "https://maps.app.goo.gl/FXrbMW6h1b7Gvp4d6",
    ticketUrl: null,
    price: null,                // string like "10€" / "Entrada gratuita" / null
    lineup: ["Mevallar"],
    poster: "/assets/posters/20260521-parallel62.jpg", // null -> placeholder treatment
    description: ""
  },
  // ...4 more entries per section 5.2
];
```

### 4.2 Templates

- `templates/concierto.html` — single-concert page template with
  `{{placeholder}}` tokens for date, venue, city, address, mapUrl,
  ticketUrl, price, lineup, poster, description.
- `templates/conciertos-listing.html` — listing page template with
  `{{upcomingCards}}` and `{{pastCards}}` insertion points, each card
  showing poster thumbnail, date, venue, city, and a "Ver detalles →" (or
  "Entradas →" when `ticketUrl` is set) `.cloud-link`.

### 4.3 Build script — `scripts/build-site.js`

Plain Node (built-in `fs`/`path` only, no npm dependencies). Responsibilities,
run end-to-end on every build:

1. Remove and recreate `dist/`.
2. Copy static site files into `dist/`: `src/index.html`, `src/style.css`,
   `src/merch/`, `src/links/`, `assets/`, and `CNAME`.
3. Read `data/concerts.js`; split into `upcoming` (date >= today) and
   `past` (date < today) lists.
4. Render `templates/concierto.html` once per concert entry → write to
   `dist/conciertos/<slug>/index.html`.
5. Render `templates/conciertos-listing.html` with the upcoming/past card
   lists → write to `dist/conciertos/index.html`.

Entries with `poster: null` render a placeholder box (styled text panel)
instead of an `<img>`.

Can be run locally for a preview (`node scripts/build-site.js`, then serve
`dist/` with any static server) and is also what the CI workflow runs.

### 4.5 Deployment — GitHub Actions

`.github/workflows/deploy.yml`:

- Trigger: push to `main` (and `workflow_dispatch` for manual re-runs).
- Permissions: `pages: write`, `id-token: write`.
- Steps: checkout → setup-node → `node scripts/build-site.js` →
  `actions/configure-pages` → `actions/upload-pages-artifact` (path:
  `dist`) → `actions/deploy-pages`.
- Only the contents of `dist/` are ever published; `scripts/`,
  `templates/`, `data/`, `src/` remain visible only in the repo (which is
  public on GitHub already), never reachable at `mevallar.com/...`.

**One-time manual step required from the user** (cannot be done via code):
repo **Settings → Pages → Build and deployment → Source: "GitHub Actions"**.
This must happen before the workflow's deploy step will succeed.

## 7. Out of scope / explicitly deferred

- No online merch store integration (in-person sales only, per user).
- No stock/availability tracking per merch item.
- No manual past/upcoming override — always computed from `date` vs. build
  time.
- No CMS or admin UI — content changes are made by editing
  `data/concerts.js` / `src/merch/index.html` directly and pushing to
  `main`.
- No dark mode / theme switcher.
- No visual mockups beyond this written spec (user declined the visual
  companion workflow; all design decisions were made via conversation and
  the three reference images in `/Users/diegocarballeda/Pictures/mev-pallete/`).
